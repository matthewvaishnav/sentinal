How SENTINEL Works

It's Express middleware that analyzes every request through multiple layers:

Request → Extract IP → Load State (Redis) ↓ Rate Limiter (sliding window, per-IP quotas) ↓ Behavioral Fingerprinting (Z-score anomaly detection) ↓ Neural Network (learns patterns, runs in worker threads) ↓ Contagion Graph (links coordinated attacks via LSH) ↓ Decision: Allow / Challenge / Block

The heavy math runs async in background workers, so your main thread stays responsive.

What Makes It Different

  • Self-learning neural network — Trains on your actual traffic, gets smarter over time
  • Zero-latency design — Heavy computation offloaded to worker threads, <1ms middleware overhead
  • Horizontally scalable — Redis-backed state means you can run 100+ nodes
  • Honeypot traps — Hidden links that only bots click, instant ban
  • P2P threat sharing — Nodes gossip about attacks in real-time via WebSocket
  • Contagion graphs — Links coordinated bot IPs using LSH clustering

Under the Hood

// Neural network architecture Input Layer: 10 features (request rate, timing, patterns) Hidden Layer: 8 neurons (ReLU activation) Output Layer: 1 neuron (sigmoid → bot probability) // Training happens async in worker pool Backpropagation: Stochastic gradient descent Learning Rate: 0.01 Training Frequency: Every 100 requests
  • Behavioral fingerprinting uses exponential moving averages to detect anomalies
  • Contagion graph uses LSH (Locality-Sensitive Hashing) to cluster similar IPs
  • P2P gossip protocol shares threat intel across nodes with proof-of-threat consensus
